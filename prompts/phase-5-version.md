# 阶段 5：版本管理

> 用途：按变化级别计算新版本号，并落地到 setup.iss。

## 规则

见 [phase-6-release.md](phase-6-release.md) 的「版本编号规则」节。本阶段只做 bump：

| 文件 | 修改 |
|------|------|
| `installer/setup.iss` | `MyAppVersion` + `MyAppVersionSuffix` |
| 其他使用版本号的文件 | 同步 |
| commit | `chore: bump version to X.Y.Zbeta` |

## 判断变化级别

```
用户能直接看到/点击/输入/感受到的变化（新按钮/页面/API/控制行为/告警类型）
  → 次版本（第二级递增）
内部重构/测试补充/日志优化/文档更新/配置调整（用户无感知）
  → 修订号（第三级递增）
用户手动指定
  → 主版本
```

## 边界示例

| 变化 | 级别 | 说明 |
|------|------|------|
| 新增导出按钮 | 次版本 | 用户可点击 |
| 趋势图固定 2h 窗口 | 次版本 | 用户可见行为变化 |
| MQTT 变量表显示名修正 | 修订号 | 界面显示修正（无新功能） |
| 数据库查询参数修复 | 修订号 | 内部机制 |
| 换生产 WSGI 服务器 | 修订号 | 用户无感知（除警告消失） |
