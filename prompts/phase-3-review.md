# 阶段 3：代码审查

> 用途：质量门禁。每次提交前（或开发完成后）执行。

## 目标

按清单审查，CRITICAL/HIGH 修复后才允许合入。

## 审查清单

```
[ ] 可读性 — 命名清晰，函数 <50 行，文件 <800 行
[ ] 不可变性 — 不修改入参，返回新对象
[ ] 嵌套深度 — 不超过 4 层，偏好 early return
[ ] 错误处理 — 每层显式处理，不静默吞异常
[ ] 安全性 — 无硬编码密钥、外部输入已验证、路径遍历防护
[ ] 测试覆盖 — ≥80%（pytest --cov=src/）
[ ] 性能 — 无 N+1 查询、无 unbounded 查询、有 pagination
```

## 严重度

| 级别 | 含义 | 处理 |
|------|------|------|
| CRITICAL | 数据丢失/崩溃 | 必须修复才能合入 |
| HIGH | bug | 合入前修复 |
| MEDIUM | 信息 | 记录 |
| LOW | 备注 | 记录 |

## 安全触发条件

**STOP → 调用 `/security-review`**：涉及 auth、用户输入、DB 查询、文件系统、外部 API、crypto、支付。

## 常见问题速查

- **安全**：硬编码凭据、SQLi、XSS、路径遍历、CSRF、auth 绕过
- **质量**：大函数/大文件、深嵌套、缺错误处理、可变性、缺测试
- **性能**：N+1 查询、缺分页、无缓存

## 执行

```bash
git diff                # 审查变更
python -m pytest tests/ # 全量回归
```
